# 집필실 원고 저장 서버

컨트롤룸의 집필 화면(`#write`)이 쓰는 원고 저장 서버다. 외부 패키지 없이 Node만으로 돈다.

## 실행

바탕화면의 "온서사 집필실" 바로가기, 또는 `scripts/start-writing-room.cmd`. 두 서버를 켜고 브라우저를 연다.

| 실행 | 원고 폴더 | 포트(저장/화면) | 화면 표시 |
|---|---|---|---|
| `start-writing-room.cmd` | `%USERPROFILE%\OnseosaData` | 3004 / 5173 | (없음) |
| `start-writing-room.cmd test` | `%USERPROFILE%\OnseosaData-test` | 3014 / 5183 | 시험 저장소 |
| `start-writing-room.cmd review` | `%USERPROFILE%\OnseosaData-review` | 3034 / 5203 | 검수 저장소 |

- 실행 스크립트(`scripts/start-writing-room.mjs`)가 모드마다 원고 폴더를 직접 지정한다.
- 저장 서버와 화면이 둘 다 응답하고, 저장 서버가 "그 모드의 원고 폴더"라고 답할 때만 브라우저를 연다. 아니면 열지 않고 이유와 다시 하는 방법을 창에 적는다.
- 포트를 다른 프로그램이 쓰고 있어도 끄지 않는다. 안내대로 그 창을 닫고 바로가기를 다시 실행한다.
- 이미 제대로 켜져 있으면 브라우저만 연다.

손으로 켤 때:

```powershell
pnpm --filter studio-server start   # 저장 서버 (127.0.0.1:3004)
pnpm --filter control-room dev      # 화면 → http://localhost:5173/#write
```

화면은 개발 서버의 프록시(`/api/studio`)로 이 서버를 부른다. 브라우저에 비밀 값을 두지 않는다.

## 원고 폴더

우선순위: `--data-root=경로` > 환경 변수 `STUDIO_DATA_ROOT` > 사용자 폴더의 `OnseosaData`.
코드 저장소 밖에 두는 것이 기본이다. 코드를 지우거나 git을 정리해도 원고가 남는다.

```text
works/<작품ID>/work.json                  제목, 원고 순서
works/<작품ID>/docs/<원고ID>.json         본문 (원고 = 회차나 장 한 편)
works/<작품ID>/versions/<원고ID>/0001.json  작가가 남긴 판 (고치지 않음)
works/<작품ID>/recovery/<원고ID>/         자동 복구본 (자동분은 40개까지)
works/<작품ID>/notes.json                 인물·설정·복선 메모
works/<작품ID>/last.json                  마지막으로 쓰던 자리
works/<작품ID>/map.json                   작품 연결 지도 (카드와 이름 붙은 연결)
works/<작품ID>/map-recovery/              지도 충돌에서 고르지 않은 쪽
```

백업 폴더는 원고 폴더 **밖**에 둔다. 우선순위: `--backup-root=경로` > `STUDIO_BACKUP_ROOT` > 원고 폴더 옆의 `<원고 폴더 이름>-backups` (예: `OnseosaData-backups`). 원고 폴더 안쪽을 지정하면 서버가 켜지지 않는다.

```text
<백업 폴더>/<작품ID>/backup-<날짜시각>-<난수>.json   작품 한 벌
```

## 지키는 것

- 모든 쓰기는 "내가 본 rev"를 비교한다. 다르면 거절(409)하고 서버 쪽 내용을 돌려준다.
- 쓰기는 임시 파일 → 디스크 동기화 → 이름 바꾸기 순서다.
- 판은 한 번 쓰면 고치지 않는다. 되돌릴 때는 직전 내용을 복구본으로 먼저 남긴다.
- 깨진 파일은 빈 것으로 취급하지 않는다. 그 위에 덮어쓰지 않고 멈춘다.
- 127.0.0.1에만 열고, 다른 출처·다른 Host의 요청은 거절하며, CORS 허용 응답을 내지 않는다.
- 목록에서 뺀 원고의 파일은 지우지 않는다.
- 제목 없이도 작품을 만든다. 화면은 첫 글자를 저장할 때 작품을 만든다.

## 저장이 안 될 때

화면 위쪽 제목 옆과 아래 상태 줄에 저장 상태가 보인다.

- **저장 실패**: 쓴 글은 이 브라우저에 보관되고 자동으로 다시 시도한다. 창을 닫지 말고 "지금 다시 시도"를 누르거나, "화면의 글 TXT로 받기"로 글을 먼저 파일로 받아 둔다. 그다음 저장 서버 창("Onseosa manuscript server …")이 떠 있는지 보고, 없으면 바로가기를 다시 실행한다. 다시 열면 보관해 둔 글을 되살려 저장한다.
- **충돌 · 저장 멈춤**: 같은 회차가 다른 탭에서 고쳐졌다. "내 글로 저장"이나 "다른 곳의 글 쓰기"를 고른다. 고르지 않은 글은 "판 › 자동 복구"에 남는다. "다른 곳의 글 쓰기"는 내 글을 보관하는 동안 입력을 잠시 잠그고, 보관에 실패하면 아무것도 바꾸지 않는다.
- **목록 저장 실패**: 새 원고·이름·순서·빼기가 서버에 저장되지 않았다. 화면의 목록은 바뀌지 않고, 쓰던 원고는 그대로 쓸 수 있다. "다시 시도"를 누른다.

## 내보내기와 백업

화면의 "내보내기"에 두 가지가 있다.

- **이 회차 TXT로 받기**: 지금 화면의 글을 한글 UTF-8 텍스트 파일로 받는다(브라우저의 다운로드 폴더). 저장되지 않은 글도 화면에 있는 그대로 담기며, 그때는 파일 이름에 `-미저장포함`이 붙는다.
- **작품 전체 백업 만들기**: 회차 순서·본문·뺀 원고·메모·판·복구본·연결 지도를 백업 폴더(원고 폴더 밖)에 파일 하나로 쓴다. 서버에 저장된 내용이 담긴다. 화면의 글이 저장되지 않은 상태면 그 사실을 알려 준다. 같은 작품 폴더 안의 "판"은 백업이 아니다.

백업 폴더는 원고 폴더와 같은 디스크에 있다. 디스크 고장까지 대비하려면 백업 파일을 다른 디스크나 클라우드에 따로 복사해 둔다.

### 복원 절차

백업은 **새 빈 폴더**에만 복원한다. 지금 쓰는 원고 폴더 위에 덮어쓰지 않는다.

```powershell
# 1. 백업 파일이 온전한지 본다 (아무것도 쓰지 않는다)
node apps/studio-server/scripts/restore-backup.mjs --backup=<백업 파일> --check

# 2. 새 빈 폴더에 복원한다. --compare 를 주면 원본과 파일 단위로 비교한다.
node apps/studio-server/scripts/restore-backup.mjs --backup=<백업 파일> --into=C:\Users\njell\OnseosaData-restored --compare=C:\Users\njell\OnseosaData

# 3. 복원본을 집필실에서 열어 본다 (검수 모드가 그 폴더를 쓰게 한다)
$env:STUDIO_REVIEW_ROOT = 'C:\Users\njell\OnseosaData-restored'
scripts\start-writing-room.cmd review
```

복원본으로 실제 원고 폴더를 바꾸는 일은 사람이 직접 한다: 집필실을 모두 끄고, 기존 `OnseosaData`의 이름을 바꿔 보관한 뒤, 복원한 폴더의 이름을 `OnseosaData`로 바꾼다.

## 작품 연결 지도

화면의 "연결 지도". 작가가 직접 만든 카드(등장인물·주제·주요 사건·조사 자료)와 두 카드 사이의 이름 붙은 연결을 본다.

- 본문이나 자유 메모를 읽어 자동으로 만들지 않는다. 비워 둬도 집필에는 영향이 없다.
- 카드와 연결은 ID로 이어진다. 이름을 고쳐도 선이 끊기지 않는다. 작품마다 `map.json`이 따로다.
- 카드에 회차를 이으면 "관련 회차 열기"로 그 회차로 가고, "쓰던 곳으로"로 지도를 열기 전의 회차·커서 자리로 돌아온다.
- 목록에서 뺀 회차는 "뺀 회차"로 표시되고, 되돌리면 다시 열 수 있다.
- 저장은 원고와 같은 규칙이다(rev 비교, 실패하면 알리고 재시도, 충돌이면 고르지 않은 쪽을 `map-recovery/`에 남김).
- 자동 추천·AI 분석·자유 배치는 없다. 카드는 종류별 칸에 자동으로 놓인다.

## 시험

```powershell
pnpm --filter studio-server test
```

임시 폴더에 서버를 띄워 시험한다. 실제 원고 폴더는 건드리지 않는다.

## 기존 집필실 원고 가져오기 (모의 실행만)

```powershell
node scripts/import-onseosalab.mjs --input=<current-project.json 복사본>
```

아무것도 쓰지 않고 개수·글자 수·해시만 보고한다. 원본 폴더 안의 파일을 주면 멈춘다. 실제로 옮기는 기능은 아직 없다.

## 시험 저장소

```powershell
scripts\start-writing-room.cmd test
```

실제와 같은 방식으로 켜되 폴더(`%USERPROFILE%\OnseosaData-test`)와 포트(3014 / 5183)만 다르다. 화면 왼쪽 위에 "시험 저장소"가 표시된다. 실제 집필실과 동시에 켤 수 있고, 브라우저 임시 보관도 서로 섞이지 않는다. 검수용으로는 `review`(폴더 `OnseosaData-review`, 포트 3034 / 5203)를 쓴다.

저장 서버는 코드가 바뀌어도 스스로 다시 켜지지 않는다. 코드를 고친 뒤에는 최소화된 서버 창을 닫고 바로가기를 다시 실행한다. 예전 버전의 저장 서버가 켜져 있으면 실행 스크립트가 알려 준다.

## 빼기와 충돌에서 남는 것

- 목록에서 뺀 원고는 `work.json`의 `removed`로 옮겨진다. 화면의 "뺀 원고"에서 되돌린다. 어디에도 남기지 않고 없애는 요청은 서버가 거절한다.
- 원고 충돌에서 고르지 않은 글은 `recovery/<원고ID>/`에 `overwrite`(밀려난 쪽)나 `stash`(내 글)로 남고, 자동 정리 대상이 아니다. 화면의 "판 › 자동 복구"에서 되돌린다.
- 메모 충돌에서 고르지 않은 메모는 `notes-recovery/`에, 지도 충돌에서 고르지 않은 지도는 `map-recovery/`에 남는다. 화면에서 꺼내 보는 기능은 아직 없다(백업에는 함께 담긴다).

## 브라우저의 원고·메모 보존

- 임시 원고·메모는 페이지마다 다른 브라우저 저장 키에 보관한다. 다른 탭의 저장 성공이 실패한 탭의 초안을 삭제하지 않는다.
- 새로고침하면 직전 페이지의 임시 보관본을 먼저 읽는다. 예전 단일 키 형식의 원고 초안도 읽을 수 있다. 서버도 바뀌었으면 자동 덮어쓰기 대신 충돌을 보여 준다.
- 인물·설정·복선 메모도 입력 즉시 임시 보관한다. 저장에 실패해도 서랍을 다시 열면 복구하고, 연결이 돌아오면 다시 저장한다.
- 이전 판으로 되돌리는 동안, 그리고 충돌에서 "다른 곳의 글 쓰기"를 처리하는 동안에는 본문 입력을 잠근다. 실패하면 현재 글을 유지하고 입력을 다시 허용한다.
- 브라우저 임시 저장 공간이 막히거나 가득 차면 경고한다. 이 상태에서는 저장 실패 후 창을 닫기 전에 내용을 별도로 복사해야 한다.

화면의 저장 장애·동시 편집 회귀 검수는 저장소 루트에서 실행한다. Node.js 22 이상과 로컬 Chrome이 필요하며, 패키지를 추가 설치하지 않는다. Chrome 위치가 다르면 `WRITING_TEST_BROWSER`에 실행 파일의 절대경로를 지정한다.

```powershell
pnpm test:writing-safety
# 결과를 남길 폴더를 지정할 수도 있다.
node scripts/test-writing-safety.mjs --output=C:/Users/njell/outputs/writing-safety
```

새 샘플 폴더·검수용 화면(5193)·숨김 브라우저 프로필을 사용한다. 실제 `OnseosaData`와 기존 `OnseosaData-test`를 사용하지 않는다. 결과 폴더에 샘플 원고·화면 캡처·`ui-results.json`이 남는다.

원고 보존(충돌·목록 장애·내보내기·백업 복원)과 연결 지도 왕복의 합격 시연도 같은 방식으로 돈다. 새 샘플 폴더·검수용 화면(5197)·숨김 브라우저 프로필만 쓴다.

```powershell
pnpm test:writing-map
node scripts/test-writing-map.mjs --output=C:/Users/njell/outputs/writing-map
```

## 이 회차의 자료와 찾기

집필 화면 위쪽의 "자료"를 누르면 지금 쓰는 회차에 이어 둔 카드(등장인물·주제·주요 사건·조사 자료)가 먼저 보인다.
같은 자리의 찾기 칸에서 이 작품의 회차 제목·본문과 카드 이름·메모·출처를 찾는다. 찾은 줄마다 종류(회차·인물·주제·사건·자료)가 적힌다.

- 카드를 고르면 출처·메모·직접 연결·관련 회차가 보인다. 넓은 창에서는 원고 옆에, 좁은 창에서는 원고 위의 한 장으로 열린다.
- "지도에서 보기"는 그 카드를 고른 채로 연결 지도를 연다. 직접 이어진 카드와 선이 강조된다.
- 여기서는 읽기만 한다. 카드·연결·회차 잇기는 연결 지도에서 한다.
- 자료나 지도에서 다른 회차를 열어도 "쓰던 곳으로"를 누르면 원래 회차·커서·스크롤로 돌아온다.
- 본문 찾기는 저장 서버가 저장된 글에서 한다(`POST /api/studio/works/<작품>/search`, 본문 `{ "q": "찾을 말" }`).
  지금 쓰는 회차만은 화면의 글에서 찾으므로 아직 저장되지 않은 문장도 나온다. 목록에서 뺀 회차는 찾지 않는다.
- 연결은 "잇기 시작한 카드 ─ 이름 → 이은 카드"로 읽힌다. 어느 쪽 카드에서 보아도 같은 문장이다.

검수: `pnpm test:writing-map` 이 390·580·1280 폭에서 이 흐름을 끝까지 돌린다.
